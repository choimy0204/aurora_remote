## 1. 시스템 개요

### 구성

| 구분 | 파일 | 역할 |
|---|---|---|
| **서버** | AuroraServer.exe | 명령 발행 · 클라이언트 모니터링 · 파일 배포 |
| **클라이언트** | AuroraClient.exe | 명령 수신 · Aurora.exe 실행/종료 · 상태 보고 |

### 통신 구조

```
[클라이언트]  3초마다 상태 보고 (POST /status)  →  [서버 :9000]
[서버]        버튼 클릭 시 명령 Push (POST /command)  →  [클라이언트 :9001]

배포 시: 서버가 \\IP\D$ (관리자 공유) 를 통해 직접 파일 복사
         → 클라이언트 HTTP 통신 불필요
```

- 버튼을 누른 순간 **온라인 클라이언트에게만 1회** 명령 전달
- 10초 이상 응답 없으면 자동 오프라인 처리

## 2. 설치 및 실행 순서

### 패키지 설치 (Python 직접 실행 시)

```bash
pip install requests psutil pystray pillow
```

### 최초 실행 순서

1. **클라이언트 PC** 에서 `AuroraClient.exe` 실행
2. 설정 패널에서 **서버 IP · 포트 · Aurora 경로** 입력 후 `적용`
3. **서버 PC** 에서 `AuroraServer.exe` 실행
4. 서버 GUI `서버 뷰` → `+ 추가` 버튼으로 **클라이언트 IP 등록** (최초 1회)
5. 클라이언트 상태가 **● 온라인** 으로 바뀌면 명령 발행 가능

> ⚠ **클라이언트를 서버보다 먼저 실행해야 합니다**

### EXE 빌드

```
D:\업무\19_Aurora 폴더에서 build.bat 실행
→ dist\AuroraServer.exe
→ dist\AuroraClient.exe
```

## 3. 서버 프로그램 (AuroraServer.exe)

서버 GUI는 3개의 탭으로 구성됩니다.

```
[ 서버 뷰 ]  [ 배포 뷰 ]  [ 단일 배포 뷰 ]
```

### 서버 뷰

#### 제어 버튼

| 버튼 | 기능 |
|---|---|
| ▶ 전체 실행 | 온라인 클라이언트 전체에 Aurora 실행 명령 전송 |
| ■ 전체 종료 | 온라인 클라이언트 전체에 Aurora 종료 명령 전송 |

#### 포트 설정

| 항목 | 기본값 | 설명 |
|---|---|---|
| 서버 포트 | 9000 | 클라이언트 상태 보고 수신 포트 |
| 클라이언트 포트 | 9001 | 클라이언트 명령 수신 포트 |

> 변경 후 `적용` → **재시작** 필요

#### 배포 버전명

- 서버 뷰에 입력한 버전명이 **배포 뷰와 공유**됩니다
- `적용` 버튼으로 `server_config.json` 에 저장

#### 클라이언트 IP 관리

| 기능 | 설명 |
|---|---|
| `+ 추가` | IP 입력 팝업 → 목록 추가 |
| `− 삭제` | 목록에서 선택 후 삭제 |
| 자동 정렬 | 추가/삭제 시 IP 오름차순 자동 정렬 |

> IP 목록은 배포 뷰 · 단일 배포 뷰와 자동으로 동기화됩니다

#### 핑 모드

| 버튼 | 동작 |
|---|---|
| Manual | 전체 핑 버튼 클릭 시에만 핑 전송 |
| Auto | 5초마다 자동으로 전체 핑 전송 |
| 전체 핑 | Manual 모드에서 즉시 전체 핑 실행 (Auto 시 비활성화) |

- 모드 변경 시 온라인 클라이언트 전체에 자동 전파
- 각 서버는 독립적으로 핑 모드 설정 (모든 서버를 동일 모드로 맞춰야 전체 동작)

#### 클라이언트 모니터링

| 항목 | 표시 | 의미 |
|---|---|---|
| 연결 상태 | ● 온라인 | 최근 10초 내 응답 |
| 연결 상태 | ○ 오프라인 | 10초 이상 무응답 |
| Aurora | ● 실행중 | Aurora.exe 프로세스 실행 중 |
| Aurora | ○ 중지 | Aurora.exe 없음 |
| 마지막 응답 | N초 전 | 마지막 상태 보고 경과 시간 |
| 핑 | Nms | 핑 응답 시간 (녹색 <10ms / 노랑 <50ms / 빨강 그 이상) |
| 핑 | 시간초과 | 핑 응답 없음 |

## 4. 클라이언트 프로그램 (AuroraClient.exe)

### 설정 패널

| 항목 | 기본값 | 설명 |
|---|---|---|
| 서버 IP | 192.168.11.7 | 서버 PC IP 주소 |
| 서버 포트 | 9000 | 상태 보고 대상 포트 |
| 수신 포트 | 9001 | 명령 수신 포트 |
| Aurora 경로 | D:\exe\aurora.exe | Aurora.exe 경로 (폴더만 입력해도 됨) |

> `Aurora 경로`는 폴더 경로만 입력하면 자동으로 `폴더\Aurora.exe` 로 실행됩니다.

### 수동 제어 (긴급용)

| 버튼 | 설명 |
|---|---|
| ▶ Aurora 실행 | 즉시 실행 (중복 실행 방지) |
| ■ Aurora 종료 | 프로세스 강제 종료 |

### 핑 상태

클라이언트 설정 탭에서 등록된 서버 IP별 핑 응답 시간을 확인할 수 있습니다.

| 색상 | 의미 |
|---|---|
| 녹색 | 10ms 미만 |
| 노랑 | 10~50ms |
| 빨강 | 50ms 이상 또는 시간초과 |

### 수신 명령 종류

| 명령 | 동작 |
|---|---|
| `start` | Aurora.exe 실행 |
| `stop` | Aurora.exe 강제 종료 |
| `setpath:<경로>` | Aurora 경로 갱신 + 레지스트리 자동 실행 경로 갱신 |
| `ping` | 등록된 서버 IP 전체 핑 실행 후 설정 탭에 결과 표시 |
| `setpingmode:<mode>` | 핑 모드 변경 (manual / auto) |

> 다른 장비의 파일을 가져오는 **반출 탭**은 [13장](#13-반출-탭--원격-장비-파일-가져오기) 참고

## 5. 포트 설정

```
서버 포트 9000  ←  클라이언트 상태 보고 (POST /status)
클라이언트 포트 9001  ←  서버 명령 Push (POST /command)
```

> ⚠ 서버의 **클라이언트 포트** = 클라이언트의 **수신 포트** 로 일치해야 합니다  
> ⚠ 포트 변경 후 방화벽 규칙도 새 포트로 추가해야 합니다

## 6. 배포 뷰 — 폴더 단위 배포

Aurora.exe 전체 폴더를 클라이언트에 배포할 때 사용합니다.

### 화면 구성

```
[소스 폴더 입력]  [폴더 선택]  [적용]  [▲ 배포하기]
버전명: 서버 뷰에서 입력한 값 공유

┌─────────────────────────────────────────────────────────┐
│ 선택 │  CLIENT   │       IP       │ 소스 폴더    │ 저장 경로      │
├─────────────────────────────────────────────────────────┤
│  ☑  │ CLIENT 01 │ 192.168.11.1   │ [v1.0.0 ▼]  │ Aurora_EXE_1.0.0.0 │
│  ☑  │ CLIENT 02 │ 192.168.11.2   │ [v1.0.1 ▼]  │ Aurora_EXE_1.0.0.0 │
│  ☐  │ CLIENT 03 │ 192.168.11.3   │ [v1.0.0 ▼]  │ Aurora_EXE_1.0.0.0 │
└─────────────────────────────────────────────────────────┘
```

### 사용 순서

1. **소스 폴더** 선택 (버전별 하위 폴더가 있는 부모 폴더)
2. **적용** → 하위 폴더 목록이 각 클라이언트 콤보박스에 채워짐
3. 각 클라이언트별 **소스 폴더(버전)** 선택
4. **서버 뷰**에서 **배포 버전명** 입력 후 적용
5. 배포할 클라이언트 **체크박스** 선택
6. **▲ 배포하기** 클릭

### 배포 경로 규칙

```
소스 부모 폴더: D:\releases
소스 폴더 선택: v1.0.0  →  실제 소스: D:\releases\v1.0.0\
버전명 입력: 1.0.0.0

결과 대상 경로: \\192.168.11.1\D$\Aurora_EXE_1.0.0.0\
```

- 배포 완료 후 클라이언트에 `setpath` 명령 자동 전송
- 클라이언트의 Aurora 경로 및 레지스트리 자동 실행 경로 갱신

### 설정 저장 항목 (server_config.json)

| 키 | 내용 | 저장 시점 |
|---|---|---|
| `deploy_src` | 소스 부모 폴더 경로 | 적용 클릭 시 |
| `deploy_version` | 배포 버전명 | 버전 적용 / 배포하기 시 |
| `deploy_client_folders` | `{IP: 선택 소스 폴더}` | 콤보박스 선택 즉시 |

## 7. 단일 배포 뷰 — 파일 단위 배포

특정 파일만 선택하여 배포할 때 사용합니다. 기존 파일을 자동으로 백업합니다.

### 화면 구성

```
[소스 폴더 입력]  [폴더 선택]  [적용]  [▲ 배포하기]

┌─ 파일 목록 ──────────┐  ┌─ 배포 대상 ──────────────┐
│ [☑] Aurora.exe       │  │ [☑] CLIENT 01  192.168.11.1 │
│ [☑] config.ini       │  │ [☑] CLIENT 02  192.168.11.2 │
│ [☐] readme.txt       │  │ [☐] CLIENT 03  192.168.11.3 │
│ ...                  │  │ ...                          │
└──────────────────────┘  └──────────────────────────────┘
```

### 사용 순서

1. **소스 폴더** 선택
2. **적용** → 폴더 내 파일 목록 표시
3. 배포할 **파일** 체크
4. 배포 대상 **클라이언트** 체크
5. **▲ 배포하기** 클릭

### 배포 동작

```
클라이언트의 동일 경로 (소스 폴더와 드라이브 기준 동일 위치)

1. 기존 파일 백업
   Aurora.exe  →  Aurora_20260608_143022.exe

2. 새 파일 복사
   서버 D:\foo\Aurora.exe  →  \\IP\D$\foo\Aurora.exe
```

- 백업 파일명 형식: `파일명_YYYYMMDD_HHmmss.확장자`
- 모든 선택 클라이언트에 **병렬** 처리
- 클라이언트 HTTP 통신 불필요 (UNC 공유 직접 접근)

## 9. 자동 실행 · Aurora 감시

### 부팅 시 자동 실행

클라이언트 최초 실행 시 레지스트리에 자동 등록됩니다.

```
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
├── AuroraClient  →  AuroraClient.exe 경로
└── AuroraApp     →  Aurora.exe 경로
```

### Aurora 감시 (Watchdog)

- 5초마다 Aurora.exe 프로세스 실행 여부 확인
- 꺼져 있으면 자동 재시작
- 배포 후 `setpath` 명령 수신 시 새 경로로 자동 전환

> 트레이 우클릭 → **종료** 선택 시에만 감시가 중단됩니다

## 10. 설정 파일 (JSON)

EXE 파일과 동일한 폴더에 자동 생성됩니다.

### server_config.json

```json
{
  "client_ips": ["192.168.11.1", "192.168.11.2"],
  "server_port": 9000,
  "client_port": 9001,
  "deploy_src": "D:\\releases",
  "deploy_version": "1.0.0.0",
  "deploy_client_folders": {
    "192.168.11.1": "v1.0.0",
    "192.168.11.2": "v1.0.1"
  },
  "deploy_user": "user",
  "deploy_pw": "1",
  "ping_mode": "manual"
}
```

### client_config.json

```json
{
  "server_ips": ["192.168.11.7"],
  "server_port": 9000,
  "listen_port": 9001,
  "aurora_path": "D:\\Aurora_EXE_1.0.0.0",
  "ping_mode": "manual",
  "export_key": "aurora-export",
  "export_relay": "192.168.110.152",
  "export_peer_port": 9001,
```

## 11. 방화벽 설정

| PC | 포트 | 방향 | 용도 |
|---|---|---|---|
| 서버 PC | TCP 9000 | 인바운드 | 클라이언트 상태 보고 수신 |
| 클라이언트 PC | TCP 9001 | 인바운드 | 서버 명령 수신 · 반출 요청 수신/중계 |

### 수동 추가 방법

1. Windows Defender 방화벽 → 고급 설정 → 인바운드 규칙 → 새 규칙
2. 규칙 종류: **포트** → TCP → 특정 로컬 포트: `9000` 또는 `9001`
3. 연결 허용 → 도메인/개인/공용 모두 체크 → 이름 입력 후 마침

> 프로그램 최초 실행 시 방화벽 허용 팝업이 나타나면 **액세스 허용** 클릭

## 12. 문제 해결

| 증상 | 조치 |
|---|---|
| 클라이언트가 오프라인으로 표시됨 | 클라이언트 실행 여부 · 등록 IP 일치 여부 · 포트 9000 방화벽 확인 |
| 전체 실행 눌러도 Aurora 안 켜짐 | ● 온라인 상태 확인 · Aurora 경로 확인 · 클라이언트 LOG 확인 |
| 서버 LOG에 전달 실패 표시 | 포트 9001 방화벽 허용 · 클라이언트 실행 여부 · 포트 번호 일치 확인 |
| 포트 변경 후 통신 안 됨 | 서버·클라이언트 모두 재시작 · 방화벽 새 포트 허용 · 포트 번호 일치 확인 |
| 중복 실행 팝업 | 트레이에 이미 실행 중 → 트레이 아이콘 우클릭 → 열기 선택 |
| 설정이 초기화됨 | EXE와 같은 폴더에 JSON 파일 존재 여부 확인 · EXE 위치 변경 시 JSON도 이동 |
| 배포 실패 (폴더/단일) | 공유 폴더(`\\IP\D$`) 접근 가능 여부 · 계정(user/1) 확인 · 방화벽 확인 |
| Aurora 경로 업데이트 안 됨 | 배포 완료 후 클라이언트가 온라인 상태인지 확인 · 클라이언트 LOG 확인 |
| 단일 배포 후 백업 파일 과다 | 클라이언트 해당 폴더에서 `파일명_날짜시간.확장자` 형태 파일 수동 정리 |
| 반출 탭이 ○ 연결 안됨 | 중계 PC IP 확인 · LHS 에서 v2.7 클라이언트 실행 여부 · LHS 포트 9001 방화벽 확인 |
| 반출 탭에 "○ 키 불일치" 표시 | 모든 PC의 `client_config.json` → `export_key` 값을 동일하게 맞춤 |
| 장비 검색에 장비가 안 나옴 | 해당 장비 클라이언트 버전(v2.7 이상) · 포트 9001 방화벽 · `장비 검색` 재시도 |
| 반출 시 "허용되지 않은 경로" | D 드라이브 · 바탕화면 밖의 경로는 반출 불가 (보안 제한) |

## 13. 반출 탭 — 원격 장비 파일 가져오기

중계 PC(LHS)를 거쳐, 내 PC와 직접 연결되지 않은 장비(CCW 등)의 파일을 **내 PC로 바로** 가져옵니다.
원격 접속 → LHS로 복사 → 다시 반출하던 과정을 한 번에 처리합니다.

### 구조

```
[내 PC 반출 탭] ──HTTP :9001──▶ [LHS Client: 중계] ──HTTP :9001──▶ [CCW Client: 파일 제공]
                ◀──── 1MB 단위 스트리밍 (LHS 디스크에 저장하지 않음) ────
```

- 서버 프로그램이나 공유 폴더(`\IP\D$`) 설정 없이 **클라이언트끼리** 동작
- 내 PC · LHS · 대상 장비 모두 **v2.7 이상 클라이언트**가 실행 중이어야 함

### 사용 순서

1. 내 PC를 LHS에 연결 → 반출 탭 상단이 **● 연결됨** 으로 바뀜 (5초마다 확인)
2. 연결되는 순간 LHS가 자기 네트워크 대역(/24)을 스캔해 **장비 목록 자동 채움**
   - 목록에 없으면 `장비 검색` 으로 다시 스캔
   - `이름` 버튼으로 표시 이름 지정 (예: CCW-1)
3. 장비 선택 → 허용 경로(D 드라이브 · 바탕화면) 표시
4. 폴더 더블클릭으로 이동, `↑ 상위` 로 복귀 (Ctrl/Shift 로 여러 개 선택)
5. `⬇ 반출` 클릭

### 반출 동작

| 항목 | 내용 |
|---|---|
| 저장 위치 | `저장 폴더\장비이름 (IP)\선택 항목` (기본: `다운로드\AuroraExport`) |
| 폴더 반출 | 하위 폴더 · 파일 전체 (빈 폴더 포함) |
| 병렬 처리 | 4개 파일 동시 전송, 진행률 · 속도 · 실패 개수 표시 |
| 취소 / 이어받기 | 받던 파일은 `.part` 로 남고 다음 반출 시 이어서 받음 |
| 수정 시각 | 원본 파일의 수정 시각 유지 |

### 보안 제한

| 항목 | 내용 |
|---|---|
| 허용 경로 | **D 드라이브 · 바탕화면만** (OneDrive 바탕화면 포함). `..` · 링크로 벗어나는 경로도 차단 |
| 반출 키 | 모든 요청에 `export_key` 필요 — **모든 PC가 같은 값**이어야 함 (기본 `aurora-export`) |
| 중계 대상 | 사설망 IP만 허용 |
| 권한 | 읽기 전용 (쓰기 · 삭제 기능 없음) |
