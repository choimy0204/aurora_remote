# Aurora WAN 원격 사용 설명서

> 출장지에서 인터넷으로 **현장 PC 화면을 보고 조작하고, 파일을 주고받는** 기능입니다.
> WAN 1.3 · 2026-10-26

---

## 먼저 알아두기

공장 안에서 쓰는 기존 기능(반입/반출 탭)은 **LAN** 입니다. **WAN 원격**은 인터넷을 건너 현장 PC에 연결하는 기능으로, 팀뷰어와 비슷하게 쓰지만 **회사가 직접 관리하는 안내 서버**를 거칩니다.

| 구분 | LAN (반입/반출 탭) | WAN 원격 (이 기능) |
|---|---|---|
| 어디서 쓰나 | 같은 공정망 (공장 안) | 인터넷 (출장지 ↔ 현장) |
| 어떻게 찾나 | 중계 PC · 장비 목록 | 안내 서버의 현장 목록 (켜진 PC만 표시) |
| 접속 확인 | 장비 선택 | 현장 PC별 **접근 코드** |
| 설정 파일 | `client_config.json` | `wan_config.json` (따로 있음) |
| 쓰는 포트 | 9000 · 9001 | 안내 서버 **9100** 하나 (현장 PC 쪽은 열 필요 없음) |
| 프로그램 | AuroraClient.exe | 같은 AuroraClient.exe 안의 **"WAN 원격" 탭** |

> 💡 **LAN 과 WAN 은 서로 독립입니다.** WAN 설정이 잘못되어도 반입/반출 탭은 그대로 동작하고, LAN 에 문제가 있어도 WAN 원격은 따로 동작합니다.

### 한눈에 보는 구조

```
[출장지 PC]  'WAN 원격' 탭 ──── 직접 연결 (가능하면) ────▶  [현장 PC]
     │                                                        ▲
     │   현장 목록 · 연결 안내 · 설정 보관                       │ 항상 연결해 둠
     └──────────────▶  [안내 서버 (회사 중계 PC)]  ◀────────────┘
                       직접 연결이 안 되면 데이터를 대신 전달 (비상 중계)
```

| 구성 | 어디에 | 하는 일 |
|---|---|---|
| **안내 서버** (`AuroraRelay.exe`) | 회사 중계 PC 1대 (계속 켜 둠) | 현장 PC 목록 관리 · 연결 안내 · 설정 보관 · 새 버전 보관 |
| **WAN 에이전트** | 현장 PC (AuroraClient 가 자동으로 시작) | 안내 서버에 계속 연결 · 접근 코드 확인 · 요청 처리 |
| **WAN 원격 탭** | 출장지 PC (AuroraClient) | 현장 목록 · 원격 연결 · 설정 보내기 · 사용량 확인 |

### 설치 순서

1. 회사 중계 PC에 **안내 서버** 설치 (1번)
2. 현장 PC에 **설정 파일** 넣기 (2번)
3. 출장지 PC에 **설정 파일** 넣고 'WAN 원격' 탭 사용 (3번)

## 빠른 시작 — 두 가지 방법

| | A. **주소로 바로 접속** (중계 PC 없음) | B. **중계 PC 를 거쳐 접속** |
|---|---|---|
| 맞는 경우 | 현장 PC 의 주소가 닿는 곳 (같은 망 · VPN · 공유기 포트포워딩을 해 둔 현장) | 현장 PC 가 공유기 뒤에 있어 주소로 닿지 않는 인터넷 너머 현장 |
| 필요한 것 | 현장 PC 의 **주소**와 **접근 코드** | 회사 중계 PC 1대 (1번 참고) |
| 현장 PC 에서 | 'WAN 원격' 탭에서 **이 PC를 원격 대상으로 사용** 체크 (끝) | 같음 + 중계 PC 에 연결 |
| 사용하는 PC 에서 | **+ 연결 추가** → 주소 입력 → 접근 코드 → **연결** | **+ 연결 추가** (또는 접속 정보 파일) → 목록에서 **더블클릭** |
| 쓰는 포트 | 현장 PC 의 TCP **9102** 하나 | 중계 PC 의 TCP **9100** 하나 |

한 PC 에서 **두 방법을 함께** 쓸 수 있습니다. 목록에 중계 PC 의 현장(방식 **중계**)과 주소로 접속했던 현장(방식 **주소**)이 같이 나옵니다.

### A. 주소로 바로 접속하기 (중계 PC 없이)

**현장 PC**
1. 'WAN 원격' 탭에서 **이 PC를 원격 대상으로 사용** 을 체크합니다.
2. 아래에 이 PC 의 **주소**(예: `192.168.0.5:9102`)와 **접근 코드**가 나옵니다. 접근 코드는 **현장 PC 가 처음 켜질 때 무작위로 자동 생성**됩니다 (직접 정하려면 칸에 입력하고 Enter — 바로 적용되고 중계 PC 에도 곧 반영됩니다).
3. 인터넷 너머에서 접속할 현장이면 공유기에서 **TCP 9102 를 이 PC 로 포트포워딩**하세요. 이 PC 가 알아낸 **공인 주소**(`공인 211.x.x.x:9102`)가 주소 옆에 함께 표시됩니다.
4. **복사**를 누르면 주소와 접근 코드가 한 줄(`AD1-…`)로 복사됩니다. 접속할 PC 에 메신저 등으로 보내면 됩니다.

**접속하는 PC**
1. **+ 연결 추가** 를 누릅니다.
2. 복사해 온 한 줄(`AD1-…`)을 붙여넣거나, **주소만** 입력합니다 (예: `192.168.0.5` — 포트를 안 적으면 9102). 주소를 입력하면 **접근 코드** 칸이 나타납니다.
3. **연결** 을 누르면 원격 창이 열리고, 그 현장은 목록에 **방식: 주소** 로 저장됩니다. 다음부터는 **더블클릭**만 하면 됩니다 (저장된 접근 코드로 바로 연결, 코드가 바뀐 경우에만 한 번 묻습니다).
4. 목록에서 지우려면 행을 선택하고 **Delete** 키(또는 오른쪽 클릭 → 목록에서 지우기).

> 💡 주소로 접속하는 현장은 목록에서 **켜짐/꺼짐**이 몇 초마다 자동으로 확인됩니다 (포트에 닿는지 확인).
> 💡 접근 코드를 5번 틀리면 1분 동안 모든 접속이 막힙니다 (중계 방식과 같음).
> 💡 중계 방식만 쓰고 주소 접속은 열어 두고 싶지 않다면 `wan_config.json` 의 `direct_listen` 을 `false` 로 바꾸세요 (바로 적용됩니다). 포트를 바꾸려면 `direct_port`.
> ⚠ 같은 망이 아닌 곳에서 주소로 접속하려면 현장 쪽 공유기의 **포트포워딩**이 필요합니다. 어렵다면 B 방식(중계 PC)을 쓰세요. 인터넷에 포트를 열 때는 **접근 코드를 기본값에서 바꾸세요**.

### 접속 정보를 파일로 옮기기 (aurora_wan.conn)

중계 PC 의 접속 정보를 **파일 하나**로 저장해 두었다가 프로그램과 함께 옮기면, 다른 PC 에서 붙여넣기 없이 자동으로 연결됩니다.

1. 중계 PC: 'WAN 원격' 탭 → **▸ 중계 PC 로 사용** 을 펼치고 **파일 저장** → `aurora_wan.conn` 으로 저장.
2. 이 파일을 **`AuroraClient.exe` 와 같은 폴더**에 넣어 새 PC 로 옮깁니다. (USB · 공유 폴더 어디든 — 프로그램과 한 폴더에 두기만 하면 됩니다)
3. 새 PC 에서 `AuroraClient.exe` 를 실행하면 **처음 한 번 자동으로 적용**됩니다 (목록 위에 **● 연결됨** 이 나타남). 현장 PC 로 쓸 거라면 **이 PC를 원격 대상으로 사용** 만 체크하세요.
- 같은 내용의 파일은 한 번만 적용합니다. 이후에 화면에서 바꾼 설정을 파일이 덮어쓰지 않고, 파일 내용을 새로 바꾸면 다시 적용됩니다.
- 찾는 위치: 실행 파일 옆 → 현재 폴더 → `D:\RemoteConfig`. 이미 쓰고 있는 PC 에서는 **+ 연결 추가 → 파일…** 로 직접 불러올 수도 있습니다.
- 파일에 공용 키가 들어 있으니 **외부에 공개하지 마세요**. 현장 PC 한 대의 주소 접속 정보(`AD1-…`)를 넣은 파일을 쓰면 그 현장이 목록에 저장됩니다.

### WAN 켜기/끄기

'WAN 원격' 탭 맨 위의 **WAN 사용** 체크가 전체 스위치입니다.
- **끄면**(처음 설치했을 때의 기본값) 중계 PC 접속 · 현장 접속 받기 · 목록 확인 · 새 버전 확인 · Git 에서 접속 정보 가져오기를 **하나도 하지 않고**, 아래 칸들도 숨습니다. 인터넷으로 아무것도 나가지 않습니다.
- **켜면** 저장해 둔 설정(현장 PC 로 사용, 중계 PC 운영, 접속 정보 등)대로 다시 시작합니다. 꺼도 설정은 지워지지 않습니다.
- 이미 WAN 을 쓰던 PC 가 새 버전으로 올라오면 켜진 채로 시작합니다 (한 번 끈 뒤에는 끈 상태가 유지됩니다).

### 사내 Git 서버로 접속 정보 배포하기

접속 정보 파일(`aurora_wan.conn`)을 **사내 Git 저장소**에 올려 두면, 다른 PC 들이 그 저장소에서 가져와 **자동으로 중계 PC 에 접속**합니다. 접속 정보는 Git 에 접근할 수 있는 회사 사람만 볼 수 있고, 공용 키를 바꿀 때도 저장소만 갱신하면 모든 PC 가 따라옵니다.

**준비 (한 번)**
1. 사내 Git 서버에 **접근이 제한된 새 저장소**를 만듭니다 (예: `https://git.회사/aurora/wan-conn.git`). ⚠ 접속 정보에는 공용 키가 들어 있으므로 **공개 저장소 · GitHub · 이 프로그램 소스 저장소에는 올리지 마세요.** 읽기 권한은 쓰는 사람만, 쓰기 권한은 중계 PC 관리자만 주세요.
2. 모든 PC(중계 PC 포함)에 **Git for Windows** 를 설치하고, **한 번 직접 `git clone` 해서 로그인(자격 증명 저장) 또는 SSH 키 등록**을 해 둡니다. 앱은 비밀번호를 물어볼 수 없습니다.

**중계 PC**
1. **자동 설정**까지 마친 뒤 '▸ 중계 PC 로 사용' 의 **Git 저장소** 칸에 저장소 주소를 넣고 **올리기**. (접속 정보 파일이 저장소에 올라갑니다)

**다른 PC (사용자 · 현장)**
1. **+ 연결 추가** 에 **그 저장소 주소**(`…git`)를 붙여넣고 **연결**. 끝입니다 — 저장소에서 접속 정보를 가져와 중계 PC 에 접속하고, 이후 **10분마다** 최신 정보를 확인합니다.
2. 연동을 끄려면 **+ 연결 추가** 창의 **Git 연동 끄기**.

### 접속 코드 새로고침 · 매일 0시 자동 갱신

중계 PC 의 '▸ 중계 PC 로 사용' 카드에서:
- **새로고침**: 접속 코드(공용 키)를 **무작위로 새로 만들어 안내 서버를 다시 시작하고 Git 에 올립니다.** **기존 접속 코드는 즉시 사라지며** 연결 중이던 원격 화면은 끊깁니다 (확인 창이 한 번 뜹니다).
- **매일 0시 자동 갱신**(기본 켜짐, **Git 저장소가 있을 때만** 동작): 매일 **자정(00:00)** 이 지나면 위와 같은 일을 자동으로 합니다. 그 시각에 PC 가 꺼져 있었다면 다시 켜질 때 한 번 합니다. 체크를 처음 켠 날은 건너뛰고 다음 날 0시부터 합니다.
- 다른 PC 는 키가 바뀌어 접속이 막히면 **30초마다** Git 을 확인해서 새 키로 자동으로 다시 붙습니다 (보통 1분 안팎).
- Git 에 올리지 못했다면(서버 점검 등) 새 키는 그대로 두고 **다시 시도**합니다. 그동안 다른 PC 는 접속이 안 될 수 있으니 오류 창의 안내를 확인하세요.
- 현장 PC 별 접근 코드는 이 새로고침과 별개입니다 (공용 키만 바뀝니다).

### 현장 목록 정리

목록에서 PC 를 고르고 **삭제**(또는 Delete 키 · 오른쪽 클릭) 하면 지워집니다. 중계 PC 에 등록된 현장은 **꺼져 있을 때만** 지울 수 있고 (그 중계 PC 를 쓰는 모든 PC 의 목록에서 사라집니다), 다시 켜지면 새로 나타납니다. **이름 바꾸기**는 중계 현장이면 설정으로 현장에 보내고(꺼져 있으면 다음 접속 때 적용), 주소로 접속한 현장이면 이 PC 에만 저장합니다.

## 1. 안내 서버 설치 · 실행 (회사 중계 PC)

회사 안에서 **항상 켜져 있는 PC 1대**에 설치합니다. 현장 PC와 출장지 PC가 모두 이 PC로 먼저 접속하므로, 주소가 바뀌지 않도록 고정 IP 를 권장합니다.

### ⓪ 가장 쉬운 방법 — 버튼 한 번으로 자동 설정

중계 PC 에도 **같은 `AuroraClient.exe`** 를 실행해 두면, 'WAN 원격' 탭에서 안내 서버를 한 번에 세팅할 수 있습니다. 키를 만들거나 포트·방화벽을 직접 만질 필요가 없습니다.

**중계 PC**
1. 'WAN 원격' 탭 아래쪽의 **▸ 중계 PC 로 사용** 을 펼치고 **자동 설정**을 누릅니다.
2. 관리자 권한이 아니면 "관리자 권한으로 다시 시작할까요?" 라고 묻습니다. **예**를 누르고 Windows 확인 창에서 **예**를 누르면, 프로그램이 관리자 권한으로 다시 켜지면서 자동 설정이 이어집니다. (**아니요**를 누르면 방화벽만 직접 열어야 합니다)
3. 자동으로 이루어지는 일: 공용 키 준비(**기본값 `aurora-wan`**, 이미 정해 둔 키가 있으면 그대로 사용) → 안내 서버 시작(포트 9100) → 방화벽 열기 → **접속 정보** 만들기.
4. 상태가 **● 운영 중** 이 되고 **접속 정보** 칸에 `AW1-...` 로 시작하는 글자가 나옵니다. **복사**를 누르거나, **파일 저장**으로 `aurora_wan.conn` 파일을 만듭니다 (위 '접속 정보를 파일로 옮기기' 참고).
5. 다른 망(출장지)에서도 쓰려면 **외부 주소** 칸에 공인 IP 또는 도메인을 적고, 공유기에서 TCP 9100 을 이 PC 로 포트포워딩하세요. 접속 정보에 외부 주소가 함께 들어갑니다.

**현장 PC · 출장지 PC**
1. 'WAN 원격' 탭의 **+ 연결 추가** 를 누릅니다. (접속 정보 파일을 `AuroraClient.exe` 옆에 두었다면 이 단계가 필요 없습니다 — 자동으로 연결됩니다)
   - **같은 망**이면 중계 PC 를 **자동으로 찾아** 접속 정보가 채워집니다. (찾는 중… → 찾았습니다)
   - 다른 망이면 중계 PC 에서 **복사**해 둔 접속 정보가 자동으로 들어옵니다. (없으면 직접 붙여넣기 또는 **파일…**)
2. 현장 PC 로도 쓸 거라면 **이 PC도 원격 대상으로 사용** 에 체크하고 **연결**.
3. 주소·공용 키가 채워지고 바로 연결됩니다. 접속 정보에 주소가 여러 개(외부·내부)면 **실제로 닿는 주소**를 자동으로 고릅니다.
4. 이후 출장지 PC 에서는 현장 목록의 PC 를 **더블클릭**하면 접근 코드를 묻지 않고 바로 원격 화면이 열립니다. 현장 PC 는 켜질 때 자기 접근 코드를 **중계 PC 에 등록**하고, 중계 PC 가 **공용 키로 접속한 PC 에게만** 그 코드를 목록과 함께 알려 주기 때문입니다. (구버전 현장 PC 처럼 코드를 등록하지 않은 현장은 공용 키가 접근 코드 역할을 합니다)

> 공용 키는 **기본값 `aurora-wan`** 으로 모든 PC 에 처음부터 들어 있어서 같은 망에서는 따로 정하지 않아도 됩니다. **인터넷에 열 때(외부 주소를 쓸 때)는 기본 키가 거부되므로**, 외부 주소를 적고 **자동 설정**을 누르면 무작위 새 키가 자동으로 만들어집니다 (7번 보안 참고). 앱이 띄우는 안내 서버는 **암호화(`wss://`)가 기본**이고, 접속 정보에 인증서 지문이 함께 들어 있습니다.
> 접속 정보에는 공용 키가 들어 있으니 **외부에 공개하지 마세요**. (같은 망 자동 찾기는 공용 키를 같은 망의 모든 PC 에 알려 주는 편의 기능이라, 믿을 수 있는 망에서만 쓰세요. 방화벽 열기를 하면 UDP 9101 도 함께 열립니다) 한 번 설정하면 다음부터는 AuroraClient 를 켤 때마다 안내 서버도 자동으로 같이 켜집니다.
> 안내 서버는 **AuroraClient 와 별도 프로세스**로 돌기 때문에 LAN 기능(반입/반출 등)에 영향을 주지 않습니다. 포트가 이미 다른 프로그램에 쓰이고 있으면 "포트 9100 를 다른 프로그램이 쓰고 있습니다" 라고 표시하고 몇 초마다 다시 시도합니다.
> **관리자 권한이 필요한 것은 방화벽 열기뿐입니다.** 관리자가 아닌 상태에서 **관리자로 다시 시작** 버튼(자동 설정 옆, 관리자가 아닐 때만 보임)으로 언제든 다시 켤 수 있습니다.
> (이 기능은 Linux·Wine 에서만 확인했고 실제 Windows 에서는 아직 확인하지 못했습니다. 특히 방화벽 열기와 관리자 권한으로 다시 시작하는 부분)

아래 ①~④ 는 **앱 없이** 안내 서버만 따로 실행하는 방법입니다 (서버 전용 PC, 시험, 작업 스케줄러 자동 실행 등).

### ① 실행하기

안내 서버는 아래 명령으로 실행합니다. 배포용으로 묶은 `AuroraRelay.exe` 를 쓰면 `python -m wan.server` 부분만 `AuroraRelay.exe` 로 바꾸면 되고, 옵션은 같습니다.

```
python -m wan.server --port 9100 --data D:\AuroraRelay --key 공용키 --update-dir D:\AuroraRelay\update
```

| 옵션 | 뜻 | 예 |
|---|---|---|
| `--port` | 받을 포트 (기본 9100) | `9100` |
| `--data` | 현장 목록과 보낸 설정을 저장할 폴더 | `D:\AuroraRelay` |
| `--key` | **공용 키**. 현장 PC 와 출장지 PC 의 설정 파일에 같은 값을 넣어야 합니다 | 길고 임의의 문자열 |
| `--update-dir` | 새 버전 파일을 넣어 둘 폴더 (5번 참고) | `D:\AuroraRelay\update` |
| `--tls` | **통신을 암호화**(`wss://`). 인증서는 `--data` 폴더에 처음 한 번 자동으로 만들어지고 지문이 출력됩니다. 인터넷에 열 때는 켜세요. 이때 접속 주소는 `wss://주소:포트` | — |
| `--host` | 받을 주소 (보통 생략) | — |

> ⚠ `--key` 를 빼고 실행하면 **누구나 안내 서버에 접속할 수 있습니다.** 반드시 키를 넣으세요.

### ② 방화벽: 포트 1개만 열기

| PC | 포트 | 방향 | 이유 |
|---|---|---|---|
| 회사 중계 PC | TCP **9100** | 들어오기(인바운드) 허용 | 현장 PC · 출장지 PC 가 접속 |
| 현장 PC · 출장지 PC | 없음 | — | 열 필요 없음 |

> 💡 포트를 바꾸면(`--port`) 설정 파일의 주소(`ws://주소:포트`, `--tls` 면 `wss://`)도 같은 포트로 맞춰야 합니다.

### ③ 항상 켜 두기

재부팅 후에도 자동으로 켜지도록 **작업 스케줄러**에 등록합니다. 동봉된 `tools\run_relay.bat` 을 중계 PC 에 복사해 두고 쓰면 편합니다.

1. `run_relay.bat` 을 열어 `CHANGE_ME` 를 실제 공용 키로 바꿉니다.
2. 작업 스케줄러 → **작업 만들기** → 트리거 **시작할 때** → 동작 **프로그램 시작** → 이 `.bat` 파일 지정
3. 설정에서 **작업이 실패하면 다시 시작** 을 켜 둡니다 (1분 간격).

### ④ 잘 떠 있는지 확인

중계 PC 나 같은 회사망의 다른 PC 브라우저에서 아래 주소를 엽니다.

```
https://중계PC주소:9100/health
```

화면에 `ok` 가 보이면 정상입니다. (암호화를 켰다면 `https://` 이고, 자체 서명 인증서라 브라우저가 경고를 띄웁니다 — 그대로 진행하세요. `--tls` 없이 실행했다면 `http://`)

## 2. 현장 PC 설치

현장 PC 관리자가 할 일은 **설정 파일 넣기**와 **프로그램 실행** 두 가지뿐입니다. 나머지는 자동입니다.

### ① 설정 파일 만들기 (회사 PC에서, 한 번)

회사 PC의 프로그램 폴더에서 아래처럼 실행합니다.

```
python tools/make_wan_config.py --relay ws://중계PC주소:9100 --key 공용키 --name "CCW 1" --out wan_config.json
```

| 옵션 | 뜻 |
|---|---|
| `--relay` | **필수.** 안내 서버 주소. `ws://` 또는 `wss://` 로 시작해야 합니다 (`http://` 는 안 됩니다) |
| `--key` | 안내 서버의 공용 키 (안내 서버에 `--key` 를 넣었을 때 같은 값) |
| `--name` | 처음 보일 이름 (예: `CCW 1`). 나중에 출장지 PC 에서 바꿀 수 있습니다 |
| `--out` | 만들 파일 위치 (기본: 현재 폴더의 `wan_config.json`) |
| `--no-enable` | 이 PC 를 **현장으로 쓰지 않을 때** 사용 (출장지 PC 용) |
| `--force` | 같은 이름의 파일이 있을 때 덮어쓰기 (없으면 덮어쓰지 않고 멈춤) |

> 💡 만들어진 파일에는 **접근 코드가 없습니다** (비워 둠). 접근 코드는 따로 정하지 않아도 되며(공용 키로 접속), 정하고 싶으면 출장지 PC 에서 '설정 보내기'로 정합니다 (3번 참고). 고유 ID 도 현장 PC 가 처음 실행될 때 자동으로 만듭니다.

### ② 현장 PC의 D:\RemoteConfig 에 넣기

1. 만든 `wan_config.json` 을 현장 PC 의 **`D:\RemoteConfig`** 폴더에 복사합니다. (폴더가 없으면 만듭니다)
2. 기존 `client_config.json` (LAN 설정)과 같은 폴더지만 이름이 달라서 서로 영향을 주지 않습니다.

### ③ AuroraClient 실행하기

1. 현장 PC 에서 `AuroraClient.exe` 를 실행합니다.
2. **WAN 에이전트는 자동으로 따로 시작됩니다.** 따로 실행할 것이 없습니다.
3. 몇 초 뒤 출장지 PC 의 'WAN 원격' 탭 목록에 현장 이름이 **● 온라인**으로 나오면 완료입니다.

> 💡 `enabled` 가 `true` 인 PC 만 WAN 원격 대상이 됩니다. 목록에 안 나오면 4번 '문제 해결'을 확인하세요.

## 3. 출장지 PC에서 쓰기

출장지 PC 에도 **같은 방식으로 `wan_config.json`** 을 넣어 두면 편합니다. 이때 `--no-enable` 을 붙여 만들면 됩니다 (출장지 PC 자신이 현장으로 켜지지 않습니다). 파일 없이 **+ 연결 추가** 로 접속 정보를 붙여넣거나 `ws://주소:포트` 와 공용 키를 입력해도 됩니다. 중계 방식은 안내 서버 주소와 공용 키가 있어야 목록을 받을 수 있습니다 (주소 방식은 필요 없음).

### ① 'WAN 원격' 탭 살펴보기

| 영역 | 내용 |
|---|---|
| **현장 PC** (목록) | 중계 PC 의 현장(방식 **중계**)과 주소로 접속했던 현장(방식 **주소**). 켜져 있으면 **켜짐**. 오른쪽 위에 중계 PC 연결 상태가 보입니다 (클릭하면 중계 PC 를 바꿈) |
| **원격 연결** | 선택한 현장 PC 에 접속합니다 (목록 더블클릭과 같음. 접근 코드를 묻지 않고 바로 연결 — 따로 정한 코드가 있을 때만 한 번 묻고 기억) |
| **+ 연결 추가** | 중계 PC 접속 정보 · 현장 PC 접속 정보(`AD1-…`) · 현장 PC 주소 중 아무거나 붙여넣거나 입력 (알아서 구분) |
| **설정 보내기** | (중계 방식 현장만) 현장 PC 의 이름 · 접근 코드 · 최고 화질 · 파일 전송 허용을 보냅니다 |
| **이 PC를 원격 대상으로 사용** | 이 PC 를 현장 PC 로 켭니다. 켜면 이 PC 의 **주소**와 **접근 코드**가 보입니다 |
| **▸ 중계 PC 로 사용** | 이 PC 가 중계 PC 일 때만 펼쳐서 사용 (자동 설정 · 접속 정보 복사/파일 저장) |
| 맨 아래 | 오늘 · 이번 달 데이터 사용량, 작은 로그 창 |

### ② 처음 접속하기

1. 현장 목록에서 현장 PC 를 고르고 **● 온라인**인지 확인합니다.
2. 현장 PC 를 **더블클릭**(또는 **원격 연결**)합니다. 접근 코드를 묻지 않고 공용 키로 바로 연결됩니다.
3. 그 현장 PC 에 **접근 코드를 따로 정해 두었다면**, 처음 한 번만 코드를 묻고 이 PC 가 기억해서 다음부터는 묻지 않습니다. (코드가 바뀌면 다시 한 번 묻습니다)
4. 몇 초 기다립니다. 먼저 **직접 연결**을 시도하고, 약 **6초** 안에 안 되면 자동으로 안내 서버를 거리는 **비상 중계**로 바꿉니다.
5. 원격 창이 열리면 현장 화면이 보입니다.

연결 방식은 화면에 이렇게 표시됩니다.

| 표시 | 뜻 |
|---|---|
| **직접 연결** | 두 PC 가 바로 연결됨 (안내 서버를 거치지 않음) |
| **비상 중계** | 직접 연결이 안 되어 안내 서버가 데이터를 대신 전달함 |
| **다시 연결 중…** | 연결이 끊겨 자동으로 다시 연결하는 중 (직접 → 중계 순으로 시도) |

원격 창 도구 막대 오른쪽에는 `직접 연결 · 이번 연결 3.1 MB · 85 KB/s · 절약` 처럼 연결 방식 · 이 연결에서 쓴 양 · 현재 속도 · 현재 화질이 표시됩니다.

> 💡 중계 상태여도 사용은 됩니다. 다만 안내 서버를 거치므로 느려질 수 있고, 데이터 사용량이 늘어날 수 있습니다.

### ③ 현장 PC 설정 보내기

현장 PC 의 설정은 현장에 가지 않아도 **이 탭에서 원격으로** 바꿉니다.

1. 현장 목록에서 현장 PC 를 고릅니다.
2. 바꿀 항목을 입력합니다.

| 항목 | 설명 |
|---|---|
| 이름 | 목록에 보이는 이름 |
| 접근 코드 | 이 현장 PC 에 접속할 때 쓰는 코드 (현장 PC 가 자동 생성하며, 여기서 바꾸면 중계 PC 가 즉시 사용자 PC 들에 알려 줌). **비워 두면 공용 키로 접속**합니다 (공용 키도 없으면 모든 접속이 거부됨). 따로 정하면 그 코드가 필요합니다 |
| 최고 화질 | 이 현장 PC 가 낼 수 있는 가장 높은 화질 (절약 · 보통 · 고화질) |
| 파일 전송 허용 | 끄면 이 현장 PC 와의 파일 반입/반출이 막힘 |

3. **설정 보내기**를 누릅니다.

> 💡 현장 PC 가 켜져 있으면 바로 적용되고, 꺼져 있으면 안내 서버가 보관해 두었다가 **현장 PC 가 연결되는 순간** 전달합니다. 현장 PC 관리자가 따로 할 일은 없습니다.

### ④ 화질 올리기

원격 창은 **항상 '절약'으로 시작**합니다 (연결할 때마다 절약으로 시작). 화면이 답답하면 창에서 화질을 올리세요.

| 화질 | 화면 크기 | 초당 최대 화면 수 | 언제 쓰나 |
|---|---|---|---|
| **절약** (기본) | 최대 1280 × 720 | 5장 | 핫스팟처럼 데이터가 적을 때, 확인만 할 때 |
| **보통** | 현장 화면 그대로 | 15장 | 일반적인 작업 |
| **고화질** | 현장 화면 그대로 | 20장 | 세밀하게 봐야 할 때 |

> 💡 화질을 올리면 데이터 사용량이 크게 늘어납니다. 필요할 때만 올리세요. (4번 참고)

**빠르게 (화면이 부드러워지지만 데이터를 약 2배 씀)**: 원격 창 도구 막대 아래의 체크박스입니다. 인터넷이 느리거나 먼 곳이면 화면을 한 장 받고 나서야 다음 장을 요청하기 때문에 초당 화면 수가 낮아집니다. 이 옵션을 켜면 **보통·고화질에서 화면을 2장씩 미리 요청**해 초당 화면 수가 거의 2배가 되지만, 겹친 요청이 같은 변화를 두 번 받아서 **데이터도 약 1.9배** 씁니다. (시험 측정: 왕복 300ms, 계속 바뀌는 화면 — 3.0 → 5.7장/초, 24.8 → 46.3 KB/s.) 기본은 꺼짐이고, **절약 화질에서는 켜도 한 장씩만** 요청합니다.

### ⑤ 파일 주고받기

원격 창 **오른쪽 패널**에서 파일을 옮깁니다.

- **반입**: 내 PC → 현장 PC
- **반출**: 현장 PC → 내 PC

현장 PC 의 **파일 전송 허용**이 꺼져 있으면 패널에서 파일을 옮길 수 없습니다 (3번 설정 보내기로 켜세요).

## 5. 새 버전 배포하기

새 버전이 나오면 **회사 중계 PC 의 업데이트 폴더에만** 넣으면 됩니다. 현장 PC 마다 가서 할 일은 없습니다.

1. 개발 PC 에서 `dist\latest` 폴더를 엽니다.
2. 그 안의 **`AuroraClient.exe`** 와 **`version.json`** 두 파일을 중계 PC 의 업데이트 폴더(`--update-dir`, 예: `D:\AuroraRelay\update`)에 복사해 덮어씁니다.
3. 끝입니다. 안내 서버 주소가 설정된 AuroraClient 는 **켜고 약 1분 뒤, 그 뒤로 6시간마다** 새 버전을 확인합니다. 새 버전이 있으면 내려받아 **SHA-256 값으로 파일이 온전한지 검사한 뒤** 스스로 교체하고 다시 시작합니다. (설정 파일의 `auto_update` 를 `false` 로 하면 이 PC 는 확인하지 않습니다.)

> 💡 교체되는 동안에는 WAN 연결이 잠시 끊길 수 있습니다.

## 6. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| **현장 PC 가 목록에 안 보임** | ① 현장 PC 에서 AuroraClient 가 켜져 있는지 ② `D:\RemoteConfig\wan_config.json` 이 있고 `enabled` 가 `true` 인지 ③ `relay_url` 의 주소와 포트가 안내 서버와 맞는지 ④ 중계 PC 에서 안내 서버가 켜져 있는지 (`/health` 확인) ⑤ 중계 PC 방화벽 9100 ⑥ 현장 PC 의 `wan_agent.log` |
| **접근 코드가 맞지 않습니다** | 대소문자와 글자를 정확히 입력했는지 (앞뒤 공백 없이) · 그 현장 PC 에 접근 코드를 따로 정해 두었는지 ('설정 보내기'로 확인) · 코드를 따로 정하지 않았다면 이 PC 의 공용 키가 현장 PC 의 공용 키와 같은지 |
| **접근 코드 잠김 (1분 뒤 다시 시도)** | 1분 안에 5번 틀리면 **1분 동안** 모든 접속이 막힙니다. 1분 기다린 뒤 맞는 코드로 다시 시도하세요. 자꾸 잠기면 누군가 틀린 코드로 접속을 시도하고 있을 수 있으니 현장 PC 의 `wan_agent.log` 에서 "접근 코드가 맞지 않는 접속 시도" 기록을 확인하세요 |
| **중계로만 연결됨** | 정상 동작입니다. 연결은 되지만 안내 서버를 거치므로 느릴 수 있고 안내 서버의 회선을 씁니다. 직접 연결이 안 되는 흔한 이유: ① 양쪽(또는 한쪽 이상)의 공유기가 **대칭형 NAT**(통신사 공유 IP 등)라서 뚫을 수 없음 ② 회사·현장 **방화벽이 UDP 를 막음**. 현장 PC 의 `wan_agent.log` 와 출장지 PC 로그에 `직접 연결이 시간 안에 맺어지지 않았습니다` 가 남습니다 |
| **안내 서버 키 불일치** | 현장 PC 와 출장지 PC 의 `wan_config.json` 에 있는 `relay_key` 가 안내 서버의 `--key` 와 **같은지** 확인하세요. 키를 바꿨다면 두 PC 의 설정 파일을 모두 다시 만들어 넣으세요 (`--force`) |
| **끊겼다 다시 연결 중** | 원격 창에 이 말이 뜨면 자동으로 다시 연결을 시도합니다. 몇 분 넘게 계속되면 인터넷 연결 · 중계 PC 상태(`/health`) · 현장 PC 의 전원과 네트워크를 확인하세요 |
| **주소로 접속이 안 됨** | ① 주소와 포트(기본 9102)가 맞는지 ② 현장 PC 에서 **이 PC를 원격 대상으로 사용**이 켜져 있고 상태에 **주소 접속 대기** 가 보이는지 ('포트 9102 를 다른 프로그램이 쓰고 있어…' 라면 `wan_config.json` 의 `direct_port` 를 바꾸세요) ③ 현장 PC 방화벽에서 TCP 9102 허용 (관리자 권한이면 자동으로 시도하며, Windows 허용 창이 뜨면 '허용') ④ 다른 망이라면 공유기 포트포워딩 ⑤ '응답이 없습니다' 는 주소·방화벽 문제, '연결이 거부되었습니다' 는 현장 PC 가 꺼져 있거나 포트가 다른 경우 |
| **현장 PC 파일 전송이 꺼짐** | '설정 보내기'에서 **파일 전송 허용**을 켜고 다시 보내세요. 현장 PC 가 꺼져 있으면 다음에 연결될 때 적용됩니다 |

## 7. 보안

WAN 은 인터넷을 지나가므로 아래 장치를 갖추고 있습니다. **앱이 알아서 해 주는 것**과 **직접 하셔야 하는 것**을 나눠 적었습니다.

### 앱이 해 주는 것

| 장치 | 내용 |
|---|---|
| **암호화** | 중계 PC 와의 통신, 주소 접속, 새 버전 내려받기가 모두 `wss://`(TLS) 입니다. 키 · 접근 코드 · 화면 · 파일이 중간에서 보이지 않습니다. 인증서는 PC 가 스스로 만들며 인증 기관이나 유료 인증서가 필요 없습니다 |
| **가짜 서버 방지(인증서 지문 고정)** | 접속 정보(`AW1-`·`AD1-`)에 상대 인증서의 지문이 들어 있어, 붙여넣은 PC 는 **그 인증서를 내민 서버에만** 접속합니다. 접속 정보 없이 주소를 직접 입력한 경우에는 **처음 접속 때 지문을 기억**하고, 이후 달라지면 거부합니다 ("인증서 불일치"). 현장 PC 를 새로 설치했다면 목록에서 지우고 다시 추가하세요 |
| **기본 키 차단** | 공용 키가 기본값(`aurora-wan`)이거나 비어 있으면, **인터넷(공인 IP)에서 오는 접속은 중계 서버가 거부**합니다. 같은 망·VPN 안에서는 기존처럼 쓸 수 있습니다. 현장 PC 의 접근 코드가 기본값일 때도 인터넷에서 오는 주소 접속을 거부합니다 |
| **강한 키 자동 생성** | 중계 PC 카드에서 **외부 주소**를 적고 **자동 설정**을 누르면, 키가 기본값일 때 **무작위 새 키**를 만들어 접속 정보에 넣습니다 |
| **현장별 무작위 접근 코드** | 현장 PC 는 처음 켤 때 자기만의 긴 무작위 코드를 만들고 중계 PC 에 등록합니다. 사람이 외우거나 입력할 필요가 없고, 현장마다 달라서 한 대만 새로 만들어 바꿀 수도 있습니다 |
| **무작위 대입 방어** | 중계 서버: 같은 곳에서 공용 키를 8번 틀리면 그곳을 5분간 차단. 현장 PC: 접근 코드를 5번 틀리면 **그 출처(IP)만** 1분간 차단 — 공격자가 주인을 막아 버릴 수 없습니다 |
| **자동 찾기 끔** | 같은 망 자동 찾기(UDP 9101)는 공용 키를 같은 망에 알려 주는 편의 기능입니다. **외부 주소를 설정하면 자동으로 꺼집니다** |
| **허용 목록** | 원격으로는 화면 · 입력 · 파일 관련 요청만 통과하고 `/command` 등 LAN 관리 기능은 항상 차단됩니다 |

### 인터넷에 열 때 직접 하셔야 하는 것 (체크리스트)

1. **중계 PC**: 'WAN 원격' 탭 → **▸ 중계 PC 로 사용** → **외부 주소**에 공인 IP 또는 도메인을 적고 **자동 설정**. (키가 새로 만들어지고 암호화가 켜진 접속 정보가 나옵니다)
2. **공유기**: TCP **9100 하나만** 중계 PC 로 포트포워딩합니다. UDP 9101 은 열지 마세요.
3. **새 접속 정보를 다시 전달**합니다 (복사 · 파일 저장). 키가 바뀌었으므로 **이미 쓰던 현장 PC · 출장지 PC 도 새 접속 정보를 한 번 붙여넣어야** 연결됩니다.
4. **공용 키가 곧 모든 현장 PC 의 열쇠**입니다. 현장마다 접근 코드가 따로 있지만, 공용 키로 접속한 PC 에게 중계 PC 가 그 코드를 모두 알려 주기 때문입니다. 공용 키를 가진 PC 를 엄격히 관리하고, 분실·유출이 의심되면 **자동 설정을 다시 눌러 공용 키를 바꾸세요.**
5. **주소 직접 접속**을 인터넷에 쓸 때는 현장 PC 에서 **접근 코드를 기본값이 아닌 값으로** 정하고, 공유기에서 TCP 9102 를 그 PC 로 포트포워딩합니다.
6. 접속 정보와 `aurora_wan.conn` 파일에는 **공용 키가 들어 있습니다.** 메신저·메일에 올리거나 USB 로 옮긴 뒤에는 지우세요.
7. 공용 키를 바꾸면 **모든 PC 에 새 접속 정보**를 줘야 합니다. 직원이 나가거나 PC 를 분실했다면 중계 PC 에서 **자동 설정을 다시 눌러 키를 새로 만드세요.**

### 알아 두실 한계

- **중계 PC 는 모든 현장의 접근 코드를 알고 평문으로 저장**합니다(`--data` 폴더의 `relay_agents.json`). 더블클릭 접속을 편하게 하려고 일부러 그렇게 만들었으므로 **중계 PC 를 믿을 수 있어야 하고**, 중계 PC 에 접근할 수 있는 사람(또는 공용 키를 아는 사람)은 모든 현장에 접속할 수 있습니다. 중계 PC 자체를 잠그세요(관리자 계정만 접근, 디스크 암호화 등).
- 비상 중계 중에는 데이터가 중계 PC 를 지나갑니다. 암호화된 채로 지나가지만 **중계 PC 관리자는 연결이 오가는 사실(누가·언제)을 볼 수 있습니다.**
- 인증서가 자체 서명이라 **처음 접속(지문을 모르는 상태)** 한 번은 가로채기에 취약합니다. 접속 정보를 붙여넣는 방식은 처음부터 지문이 들어 있어 안전합니다. 가능하면 주소를 직접 입력하지 말고 접속 정보를 쓰세요.
- 접근 코드 · 공용 키는 각 PC 의 `wan_config.json` 에 **글자 그대로** 적혀 있습니다. 이 파일을 보내지 마세요. 개인 키가 든 `*_cert.pem` 도 마찬가지입니다.
- 공용 키가 길고 임의인 값이라면 무작위 대입은 현실적으로 불가능하지만, **짧거나 사전에 있는 단어**는 막지 못합니다. 직접 정할 땐 12자 이상 임의의 글자를 쓰세요.
- 이 보안 장치는 **WAN 쪽에만** 적용됩니다. 기존 LAN(반입/반출)의 보안은 그대로이며, WAN 설정이 LAN 에 영향을 주지 않습니다.
- 개발 환경(Linux · Wine)에서 시험했고 실제 Windows 와 실제 인터넷에서의 침투 시험은 하지 않았습니다. 중요한 현장에 쓰기 전에는 IT 담당자의 점검을 받으세요.

## 8. 참고 — 포트 · 파일 · 로그 위치

### 포트

| 포트 | 어디 | 용도 |
|---|---|---|
| TCP **9100** | 회사 중계 PC (들어오기 허용) | 안내 서버 접속 (`--port` 로 변경 가능) |
| TCP **9102** | 현장 PC (주소로 바로 접속을 받을 때만) | 주소 접속 (`wan_config.json` 의 `direct_port`). 중계 방식만 쓰면 열 필요 없음 |
| UDP **9101** | 회사 중계 PC (같은 망에서 중계 PC 자동 찾기) | 방화벽 열기 시 함께 열림 |
| 없음 | 출장지 PC | 열 필요 없음 |

> 💡 WAN 은 LAN 이 쓰는 포트(9000 · 9001)를 쓰지 않습니다.

### 파일 위치

| 파일 | 어디 | 내용 |
|---|---|---|
| `D:\RemoteConfig\wan_config.json` | 현장 PC · 출장지 PC | WAN 설정 (안내 서버 주소, 공용 키, 이름, 접근 코드, 주소로 접속했던 현장 등) |
